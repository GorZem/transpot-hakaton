# Эмулятор участка Люблино

Заменяет улицу для системы управления светофорами. Моделирует движение машин и пешеходов на пяти
улицах Люблино (геометрия из OpenStreetMap), рендерит изображение с камер объектов пилота на видеокарте
и принимает команды светофорам.

Для системы эмулятор выглядит как оборудование на улице:

| Что | Как в жизни | Как в эмуляторе |
|---|---|---|
| Камеры | IP-камера отдаёт поток | `GET /cam/{camera_id}.mjpg` (MJPEG), кадр `GET /cam/{camera_id}.jpg` |
| Светофор | дорожный контроллер принимает команды | `PUT /api/objects/{object_id}/signals` |

Внутреннюю логику эмулятора система не использует. Всё остальное (карта, сценарии, «истина») нужно
для демонстрации и отладки.

## Запуск

```powershell
./run_emulator.ps1            # Windows: окружение, зависимости, запуск
./run_emulator.ps1 -Window    # плюс 3D-окно с видом на участок
```
```bash
python -m venv .venv && .venv/bin/pip install -r emulator/requirements.txt
.venv/bin/python -m emulator            # http://127.0.0.1:8100
```

Нужны Python 3.10+ и видеокарта с OpenGL (проверено на RTX 3050).

Откройте `http://127.0.0.1:8100/`, там живая карта участка, камеры и ручное управление светофорами.
Swagger с описанием API: `http://127.0.0.1:8100/docs`.

Параметры: `--port`, `--fps 10`, `--width 960 --height 540`, `--traffic 1.0`, `--pedestrians 1.0`,
`--watchdog 20`, `--msaa 0` (сглаживание кадров: 2 или 4 — красивее, но почти вдвое дороже),
`--on-demand` (рендерить только камеры, которые кто-то смотрит), `--window`.

Управление в 3D-окне: левая кнопка мыши — поворот вокруг вертикали и наклон, правая — сдвиг по земле,
колесо — масштаб, клавиши 1–0 — перейти к объекту, R — общий вид. Камера не заваливается вбок и всегда
смотрит сверху, земля остаётся внизу кадра.

## Объекты и камеры

10 объектов, у каждого 2 камеры (`{object_id}-cam1`, `{object_id}-cam2`). Идентификаторы объектов совпадают
с `data/sites.json` системы.

| object_id | Тип | Группы светофора |
|---|---|---|
| `p-krasnodonskaya-south`, `p-krasnodonskaya-mid`, `p-krasnodonskaya-north`, `p-krasnodarskaya`, `p-stavropolskaya` | переход | `veh`, `ped` |
| `x-krasnodarskaya-krasnodonskaya`, `x-krasnodonskaya-stavropolskaya`, `x-krasnodarskaya-novorossiyskaya`, `x-krasnodonskaya-sovkhoznaya` | крестовой | `veh_A`, `veh_B`, `ped_A`, `ped_B` |
| `t-novorossiyskaya-stavropolskaya` | Т-образный | `veh_A`, `veh_B`, `ped_A`, `ped_B` |

На перекрёстке ось `A` — главная улица (для Т-образного это сквозная улица), ось `B` — пересекающая.
`ped_A` — пешеходы, пересекающие рукава оси A, они идут параллельно транспорту оси B. Названия улиц
осей есть в `GET /api/objects/{id}` → `axes`.

Размещение камер: на опорах высотой 6 м, широкоугольные (около 125° по горизонтали).
- Переход: по разные стороны дороги, смотрят в разные стороны. Каждая видит свой подход машин, переход
  и зону ожидания на противоположной стороне.
- Крестовой: противоположные углы по диагонали, каждая смотрит на дальний угол.
- Т-образный: одна напротив примыкания, вторая на углу примыкания.

### Искажение объектива

Кадр искажён как у широкоугольной камеры (модель OpenCV). Калибровка есть в `GET /api/cameras/{id}` → `calibration`:

```python
import cv2, numpy as np, requests
cam = requests.get("http://127.0.0.1:8100/api/cameras/p-krasnodonskaya-mid-cam1").json()
K, D = np.array(cam["calibration"]["K"]), np.array(cam["calibration"]["D"])
cap = cv2.VideoCapture("http://127.0.0.1:8100/cam/p-krasnodonskaya-mid-cam1.mjpg")
ok, frame = cap.read()
flat = cv2.undistort(frame, K, D)
```

## Управление светофором

```http
PUT /api/objects/p-krasnodonskaya-mid/signals
{"groups": {"veh": "yellow"}}
```

Состояния транспорта: `red`, `red_yellow`, `green`, `green_blink`, `yellow`, `flash_yellow`, `off`.
Пешеходов: `red`, `green`, `green_blink`, `off`. Можно менять одну группу или несколько сразу.

Режимы объекта (`signal.mode`):
- `local`: работает собственная фиксированная программа. Это состояние после запуска.
- `remote`: первая принятая команда передаёт управление системе. Объект держит последние состояния.
- `flash`: жёлтый мигающий.

Правила контроллера, как у настоящего:
- **Конфликт-монитор.** Если команда даёт одновременно движение конфликтующим группам (например, `veh` и
  `ped` на переходе или `veh_A` и `ped_A` на перекрёстке), объект уходит в `flash`, ответ `409`.
  Дальнейшие команды отклоняются до `POST /api/objects/{id}/reset`.
- **Порядок сигналов.** Нарушение (например, `green → red` без жёлтого) исполняется, но пишется в журнал
  и возвращается в `message`.
- **Сторожевой таймер.** В режиме `remote` нужно присылать команду или `POST /api/objects/{id}/heartbeat`
  не реже чем раз в 20 с (`--watchdog`). Иначе объект вернётся к локальной программе.
- `POST /api/objects/{id}/release` возвращает локальную программу.

Правильный цикл перехода, который система должна выдавать сама:
`veh: green → green_blink (3 с) → yellow (3 с) → red`, затем «все красные» 2 с,
`ped: green → green_blink (3 с) → red`, «все красные», `veh: red_yellow (2 с) → green`.

## Сценарии и отладка

| Запрос | Что делает |
|---|---|
| `POST /api/objects/{id}/pedestrians {"count": 10}` | группа пешеходов у перехода объекта |
| `POST /api/objects/{id}/emergency` | скорая с маячками едет через объект |
| `POST /api/cameras/{id}/fault {"fault": "black"}` | неисправность: `black`, `freeze`, `offline`, `noise`, `null` — исправна |
| `PUT /api/scenario {"traffic_scale": 1.6, "pedestrian_scale": 2}` | интенсивность транспорта и пешеходов |
| `POST /api/traffic/clear {"cars": true, "pedestrians": true}` | убрать машины и/или пешеходов (новые продолжат появляться на въездах) |
| `POST /api/traffic/fill {"per_km": 8}` | сразу расставить машины по пустым полосам |
| `GET /cam/{camera_id}/labeled?min_px=12` | кадр и разметка на этом же кадре для дообучения детектора (см. ниже) |
| `GET /api/objects/{id}/truth` | фактическая обстановка: кто ждёт, сколько машин на подходах. Для проверки распознавания |
| `GET /api/objects/{id}/events` | журнал контроллера объекта |
| `GET /cam/overview.mjpg` | 3D-обзор выбранного объекта (`POST /api/overview {"object_id": ...}`) |

### Разметка кадров для дообучения

`GET /cam/{camera_id}/labeled` отдаёт свежий кадр и рамки всех машин и людей **на этом же кадре**.
Разметка считается в момент постановки кадра на рендер из того же состояния сцены, рассинхрона нет.

```json
{"camera_id": "p-krasnodonskaya-mid-cam1", "frame_seq": 812, "frame_ts": 1790520000.1, "sim_time_s": 912.4,
 "width": 960, "height": 540, "fault": null, "calibration": {"K": [...], "D": [...]},
 "objects": [{"id": "ped-311", "class": "person", "bbox": [612.0, 288.5, 631.2, 340.9],
              "occluded_frac": 0.0, "occluded_by_buildings": 0.0, "truncated": false, "visible": true,
              "distance_m": 17.3, "state": "waiting", "crossing_on_red": false, "crosswalk_id": 36, "group": false},
             {"id": "car-88", "class": "car", "bbox": [...], "speed_mps": 0.0, ...}],
 "image_jpeg_base64": "..."}
```

- `bbox` = [x1, y1, x2, y2] в пикселях выходного кадра, то есть с искажением объектива. Рамка — проекция
  8 углов 3D-габарита агента той же моделью камеры (k1, k2), обрезанная краем кадра (`truncated`).
- Классы: `car`, `bus`, `truck`, `emergency`, `person`.
- Агенты, полностью закрытые домами, не возвращаются. `occluded_frac` — доля агента, закрытая домами
  или более близкими агентами (для агентов приближённо, по перекрытию рамок). `visible` = `occluded_frac < 0.9`.
  Деревья и опоры не учитываются.
- Параметры: `min_px` (по умолчанию 12) — отбросить рамки, у которых и ширина, и высота меньше;
  `include_hidden=true` — вернуть и почти закрытые; `image=false` — без JPEG.
- При неисправности `freeze` или `offline` ответ `409`, при `black`/`noise` поле `fault` заполнено.

## Как устроено

```
emulator/
  world/network.py   дорожная сеть из OSM: полосы, манёвры, переходы, узлы светофоров
  world/signals.py   светофорный контроллер: программа, команды, конфликт-монитор, сторожевой таймер
  world/sim.py       машины (модель IDM), пешеходы, скорая, «истина»
  render/scene.py    3D-сцена Panda3D: дороги, разметка, дома, деревья, светофоры, машины, люди
  render/cameras.py  расстановка камер, рендер в текстуру, искажение, JPEG
  render/labels.py   разметка кадра: рамки агентов с учётом искажения и закрытости
  render/models.py   процедурные модели машин (седан, хэтчбек, кроссовер, автобус, грузовик, скорая) и людей
  render/visibility.py зона видимости камер: скрытие моделей и упрощение карты вне её
  app.py             сборка эмулятора (модель, сцена, камеры) для запуска и замеров
  tools/eval_detection.py  доля людей и машин, которые находит YOLO, по разметке эмулятора
  tools/bench.py     замер производительности со всеми камерами
  tools/traffic_check.py  качество движения: наезды, пропускная способность
  server/api.py      HTTP API и видеопотоки
  server/static/     веб-интерфейс: карта и панель объекта
  data/              выгрузка OSM (© участники OpenStreetMap, ODbL)
```

Модель идёт в реальном времени с шагом 50 мс.

### Производительность

Все 20 камер работают всегда, независимо от того, смотрит ли их кто-то (`--on-demand` включает старый
режим «по запросу»). Чтобы это было дёшево:
- машины и люди вне зоны видимости камер продолжают двигаться в модели, но их 3D-модели убраны из сцены;
- вне зоны камер карта упрощена: дома без окон, без деревьев, бордюров и прерывистой разметки;
- позы шага людей заранее «запечены» в цельные модели, машина — одна модель со своим цветом;
- рендер без сглаживания с масштабом 0,85: выходной кадр по-прежнему 960×540.

На RTX 3050 все 20 камер выдают около 9,5 кадра/с при цели 10 (`python -m emulator.tools.bench`).
Готовая YOLO11s на этих кадрах находит около 97% людей и 81% машин (видимых хотя бы наполовину,
рамка от 24 px; `python emulator/tools/eval_detection.py --model yolo11s.pt`). Для дообучения берите
разметку из `/cam/{id}/labeled`.

### Движение машин

- **Полосы по разметке.** На подъезде к перекрёстку левая полоса — налево, правая — направо, средние — прямо;
  на двух полосах левая «налево и прямо», правая «прямо и направо». На асфальте нарисованы стрелки
  и сплошная за 15 м до стоп-линии.
- **Перестроение.** Машина заранее выбирает манёвр на следующем перекрёстке и перестраивается в нужную
  полосу, выбирая безопасный интервал. Там, где улица сужается, лишняя полоса заканчивается, и машины
  встраиваются «застёжкой», соседи оставляют им место. Не успевшая перестроиться до сплошной едет туда,
  куда ведёт её полоса.
- **Перекрёсток.** Для каждой пары манёвров известна зона, где их траектории сходятся ближе 2,4 м.
  Машина не въезжает в зону, пока её занимает другая. Поворачивающий налево въезжает на перекрёсток
  и ждёт внутри, пропуская встречных. Никто не останавливается в чужой зоне; простоявшая внутри
  перекрёстка дольше 8 с машина завершает манёвр, чтобы не было затора.
- **Слияние в одну полосу** («застёжка»): машина, которая ближе к точке слияния, едет первой.
- Пешеходов на переходе пропускают, если они у траектории машины (в пределах 3 м).

Интенсивность ×1 подобрана так, чтобы очереди не росли: при ней за полчаса модельного времени на участке
стабильно 70–120 машин, наездов почти нет (`python -m emulator.tools.traffic_check --minutes 30`).
При ×1,5 и выше на фиксированных программах очереди растут — режим «час пик» для демонстрации
адаптивного управления.

Ограничения:
- Машины не обгоняют: перестраиваются, только чтобы занять полосу своего манёвра.
- Графика упрощённая: деревья и опоры в разметке кадров не учитываются.

Тесты: `python -m pytest emulator/tests`.
