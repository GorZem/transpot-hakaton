# SmartCross — умный регулируемый пешеходный переход

Решение кейса ООО «Смарт Си» для ИТ-чемпионата «Цифровая Эра Транспорта».

Светофорный объект, который вместо жёсткого цикла или кнопки вызова **видит** обстановку.
YOLO распознаёт пешеходов и транспорт, по плотности потока и числу ждущих людей система
решает, когда включать пешеходную фазу.

- Дорога пуста: пешеход получает зелёный **через 2 с**.
- Поток плотный: пешеходная фаза включается, когда выигрыш пешеходов перевешивает задержку
  водителей и пассажиров. Критерий накопленной задержки, [подробно](docs/algorithms.md#4-когда-включать-пешеходную-фазу).
- Группа 5–10+ человек проходит заметно раньше одиночки.
- Спецтранспорт: зелёный машинам удерживается.
- Отказ камеры: деградированный или фиксированный режим, возврат после стабилизации.
- Независимый **конфликт-монитор** не даёт одновременно разрешить движение машинам и
  пешеходам. При любом сомнении — жёлтый мигающий.

## Результаты

Моделирование: 4 сценария × 5 прогонов по 2 ч, одинаковые потоки для всех стратегий.
Полная таблица и методика: [docs/algorithms.md](docs/algorithms.md#7-результаты-моделирования).

| Сценарий | Ожидание пешехода, с: фикс. цикл / кнопка / **SmartCross** | Переходят на красный |
|---|---|---|
| Ночь, пустая дорога | 18,3 / 11,1 / **8,9** | 17% / 19% / **0,4%** |
| День, низкая интенсивность | 17,7 / 14,2 / **11,6** | 17% / 12% / **1,8%** |
| День, средняя интенсивность | 18,7 / 14,7 / **13,3** | 17% / 12% / **5,8%** |
| Час пик + группы | 18,1 / 14,8 / **14,7** | 17% / 11% / **10,4%** |

![Сравнение стратегий](reports/simulation.png)

Проверка на реальных видео переходов в Тюмени (Wikimedia Commons, CC BY-SA):
`python scripts/replay.py --camera cam2 --out reports/replay/cam2.mp4`.
Скрипт пишет размеченный ролик и выдаёт счётчики: ТС по линии, пешеходы, ждущие.

## Быстрый старт

```bash
python3 -m venv .venv
.venv/bin/pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python scripts/fetch_videos.py        # демо-видео (≈ 10 МБ)
.venv/bin/python -m smartcross                  # http://localhost:8000
```

Или `docker compose up --build`. Веса YOLO11n (6 МБ) скачиваются автоматически при первом
запуске.

Интерфейс:
- **Мониторинг** — светофор, отсчёт, режим и его причина, живое видео с разметкой, обстановка
  (кто ждёт, интенсивность, окно усреднения, плотность), журнал фаз и событий.
  Кнопки имитации отказа камер и виртуальная кнопка вызова.
- **Настройка** — все параметры с подсказками и пределами. Форма строится по схеме конфига,
  значения валидируются на сервере и применяются на лету без перезапуска.
  Редактор зон прямо на кадре камеры.
- **Статистика** — транспорт и пешеходы по времени, интенсивность и плотность, ожидание,
  распределение ожидания, состав потока, время в режимах, экспорт CSV.

## Проверка

```bash
.venv/bin/python -m pytest -q                        # 32 теста
.venv/bin/python -m smartcross.sim --hours 2         # сравнение стратегий → reports/
.venv/bin/python scripts/tune.py                     # подбор параметров алгоритма
.venv/bin/python scripts/camera_geometry.py          # расчёт обзора камеры
```

Что покрыто тестами:
- **Контроллер**:
  - сценарии: пустая дорога, плотный поток, группы, разрыв в потоке, спецтранспорт,
    продление «всё красное», фиксированный, деградированный и мигающий режимы;
  - **property-based** (hypothesis): сотни случайных последовательностей наблюдений и смен
    режимов, ни разу нет конфликта сигналов и превышения предельного ожидания.
- **Оценка потока**: точность на 300/1200/3000 авт/ч, подстройка окна, реакция на скачок.
- **Зоны**: попадание в зоны, пересечение линии (в т.ч. с пропуском кадров и точкой ровно
  на линии), уникальный счёт пешеходов.
- **Интеграция**: реальные потоки камер на синтетическом видео, имитация обрыва и зависания,
  переходы ADAPTIVE → DEGRADED → FIXED → ADAPTIVE, запись статистики.

## Архитектура

```
 камеры (RTSP/файл/USB)
   │  CameraWorker (поток на камеру): кадр → YOLO11n + ByteTrack → зоны → FrameResult
   │                                   здоровье: обрыв / зависание / закрыта
   ▼
 Engine (10 Гц): слияние камер → Observation ─┬─ выбор режима (здоровье камер, ночь, оператор)
   FlowEstimator: интенсивность за адаптивный │
   интервал, плотность                        ▼
                                  Controller (автомат фаз, решение о пешеходной фазе)
                                              │
                    ConflictMonitor ◄─────────┤
                                              ▼
                               SignalOutput: mock / GPIO-реле (+ вход кнопки)
   StatsDB (SQLite/PostgreSQL): трафик по минутам, фазы, ожидания, события
   FastAPI + веб-интерфейс: мониторинг, настройка, статистика
```

| Модуль | Что делает |
|---|---|
| `smartcross/vision/` | детектор YOLO, маячки спецтранспорта, зоны, поток камеры |
| `smartcross/traffic/flow.py` | интенсивность с адаптивным окном, плотность |
| `smartcross/controller/` | тайминги (Вебстер, пропускная способность, стоимость фазы), автомат фаз, конфликт-монитор |
| `smartcross/engine.py` | слияние, здоровье камер, режимы, статистика |
| `smartcross/stats/db.py` | хранение и выборки статистики |
| `smartcross/hw/output.py` | выход на светофор |
| `smartcross/web/` | API и интерфейс |
| `smartcross/sim/` | симулятор для сравнения стратегий |

## Ограничения и что дальше

- Демо-видео сняты с рук и с уровня тротуара, поэтому зоны «плавают» вместе с кадром. На
  штатной камере на опоре кадр неподвижен.
- Спецтранспорт определяется эвристикой по проблесковому маячку. Для эксплуатации нужна модель,
  дообученная на спецтехнике; подключается через `detector.emergency_classes`.
- Выход на светофор реализован через GPIO-реле. Для реального объекта нужна интеграция с
  конкретным дорожным контроллером: вход «вызов фазы» или протокол контроллера.
- Параметры алгоритма подобраны на модели. Перед внедрением их нужно откалибровать по данным
  с реального объекта: статистика для этого уже собирается.
