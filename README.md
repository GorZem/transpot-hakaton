# Умные переходы Люблино

Система управления светофорами на пешеходных переходах и перекрёстках по данным камер.
Решение кейса ООО «Смарт Си» для ИТ-чемпионата «Цифровая Эра Транспорта».

Камеры видят, кто ждёт у перехода и что происходит на подходах. Контроллер решает, когда
включить пешеходам зелёный. Пилотный участок: 10 объектов в Люблино (5 переходов,
4 крестовых перекрёстка, 1 Т-образный), координаты и адреса взяты из OpenStreetMap.

## Запуск

Windows:

```powershell
.\run.ps1
```

Скрипт создаёт `.venv`, ставит зависимости (torch с CUDA, для процессора `-Cpu`), собирает
админку и открывает http://127.0.0.1:8000. Нужны Python 3.11+ и Node.js 20+.

Вручную:

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt
cd admin && npm ci && npm run build && cd ..
.venv/Scripts/python -m center
```

Разработка админки с горячей перезагрузкой: `python -m center` и в другом окне `cd admin && npm run dev`
(Vite проксирует `/api` и `/ws` на центр).

Тесты: `.venv/Scripts/python -m pytest -q`.

## Устройство

```
node/     узел объекта: источник данных → наблюдение → режим → контроллер → защита → светофор
center/   центр: хаб объектов, SQLite, REST и WebSocket, поиск, статистика
admin/    админка: карта с поиском, страница объекта (мониторинг, статистика, настройки)
data/     sites.json — объекты Люблино из OSM
tools/    osm_import.py — пересобрать sites.json из OpenStreetMap
tests/
```

**Узел** (`node/`) один на объект и работает одинаково внутри центра или на встраиваемом ПК у светофора:

- `model.py`: группы сигналов, фазы, конфликты и камеры для перехода, Т-образного и крестового
  перекрёстка;
- `control.py`: общий механизм фаз и переходных интервалов по ГОСТ Р 52289 (зелёный мигающий,
  жёлтый, все красные, красный с жёлтым). На переходе задержка включения пешеходной фазы
  зависит от интенсивности, на пустой дороге и при разрыве в потоке зелёный даётся быстро,
  группа от N человек ускоряет вызов, есть предел ожидания. На перекрёстке фаза продлевается,
  пока подходят машины, фазы без спроса пропускаются, пешеходы и спецтранспорт получают приоритет;
- `safety.py`: модуль безопасности, независимый от логики решений. Проверяет конфликты сигналов,
  порядок и минимальные длительности тактов, промежуточный такт. При нарушении переводит
  объект в жёлтый мигающий;
- `flow.py`: интенсивность с адаптивным окном: окно растягивается до N машин в пределах 1–10 мин;
- `runtime.py`: выбор режима по исправности камер (адаптивный, деградированный, фиксированный
  план) и минутная статистика;
- `synthetic.py`: тестовый источник данных, пока к объекту не подключено видео.

**Центр** (`center/`) крутит узлы в реальном времени, пишет статистику и события в SQLite
и отдаёт их админке. История за прошлую неделю сгенерирована для демонстрации и помечена
в админке как демонстрационная.

## Статус прототипа

Готово: 10 объектов, контроллеры всех трёх типов, модуль безопасности, аварийные режимы,
центр, админка с картой, поиском, мониторингом, статистикой и настройками, 21 тест.

Дальше: распознавание на видео (YOLO + трекинг) вместо тестового источника, отдельный
процесс узла для встраиваемого ПК, эмулятор участка.
