# Умные переходы Люблино

Система управления светофорами на пешеходных переходах и перекрёстках по данным камер.
Решение кейса ООО «Смарт Си» для ИТ-чемпионата «Цифровая Эра Транспорта».

Две широкоугольные камеры на объекте видят, кто ждёт у переходов и что происходит на подходах.
Система распознаёт пешеходов и транспорт (YOLO), переводит их в метры по калибровке камер
и решает, когда включать пешеходам зелёный. Команды уходят на дорожный контроллер объекта.

Участок: 14 светофорных объектов в Люблино — 5 переходов, 5 крестовых и 4 Т-образных
перекрёстка. Все оснащены двумя камерами (28 камер) и управляются системой.

## Как это подключено

Система работает с оборудованием на улице так же, как с настоящим:
- **камеры** отдают видео MJPEG (`/cam/<id>.mjpg`);
- **дорожные контроллеры** принимают команды групп сигналов по HTTP (`PUT /api/objects/<id>/signals`,
  `heartbeat`, `release`). Без команд контроллер через 20 с возвращается к своей программе.

Сейчас «улица» — эмулятор участка (ветка `emulator`). Адрес задаётся в `config/center.yaml`.
Отказы камер, группы пешеходов, спецтранспорт создаются в эмуляторе. Система их не имитирует,
а обнаруживает сама: отказ камеры — по изображению (нет потока, чёрный кадр, зависание, помехи).

Камеры поворотные: оператор поворачивает их из админки (кнопка «Повернуть камеры» на мониторинге
или редактор зон в настройках), ход — ±90° по азимуту от положения при монтаже. Центр постоянно
опрашивает положение камер (`GET /api/cameras/{id}/ptz` у оборудования), поэтому замечает и поворот
не из админки (ветер, монтажник). Пока камера поворачивается, объект работает по фиксированному плану;
после остановки центр пересчитывает калибровку и зоны: автоматические — заново, нарисованные вручную —
переносом через плоскость земли. Положение камер хранится вместе с разметкой.

Фиксированный план включается и тогда, когда распознавать не по чему: ни одна камера объекта не даёт
пригодного изображения (нет видимости — туман, грязь, закрыт объектив; чёрный кадр; ни людей, ни машин
дольше параметра «Пустая сцена», по умолчанию 120 с) или не работает компьютерное зрение (детектор не
загрузился, упал или не отвечает 6 с). Такие камеры в админке отмечены оранжевым, неисправные — красным.
Если непригодна одна камера из двух — деградированный режим. Проверить отказ распознавания:
`POST /api/system/detector {"paused": true}`.

Паспорта объектов (группы сигналов, геометрия переходов и подходов, положение и калибровка камер)
лежат в `data/sites.json`. Их собирает `tools/sync_emulator.py`: аналог исполнительной съёмки
при монтаже. После изменений в эмуляторе паспорта нужно пересобрать.

## Запуск

1. Запустить эмулятор (ветка `emulator`): `python -m emulator` → http://127.0.0.1:8100.
2. Запустить центр:

```powershell
.\run.ps1
```

Скрипт создаёт `.venv`, ставит зависимости (torch с CUDA, для процессора `-Cpu`), собирает
админку и открывает http://127.0.0.1:8000. Нужны Python 3.11+ и Node.js 20+.

Проверка качества распознавания против «истины» эмулятора:
`.venv\Scripts\python tools\check_perception.py`.

Тесты: `.venv\Scripts\python -m pytest -q`.

## Устройство

```
node/     узел объекта: источник данных → наблюдение → режим → контроллер → защита → светофор
center/   центр: хаб объектов, SQLite, REST и WebSocket, поиск, статистика
admin/    админка: карта с поиском, страница объекта (мониторинг, статистика, настройки)
config/   center.yaml — адрес оборудования, детектор
data/     sites.json — паспорта объектов
tools/    sync_emulator.py — паспорта из эмулятора; check_perception.py — проверка распознавания
tests/
```

**Узел** (`node/`) один на оснащённый объект и работает одинаково внутри центра или на встраиваемом ПК у светофора:

- `vision/camera.py`: приём видео и контроль исправности камеры по изображению;
- `vision/detector.py`: YOLO на видеокарте, кадры всех камер обрабатываются пакетом;
- `vision/geometry.py`: калибровка камеры (широкоугольный объектив, модель OpenCV): пиксель → точка
  на земле в метрах; зоны объекта: переходы, зоны ожидания, подходы и стоп-линии;
- `perception.py`: слияние детекций двух камер, треки на земле, время ожидания каждого пешехода,
  очереди и подходящие машины, события «перешёл» (и на какой сигнал), «проехал», «останавливался»;
- `model.py`, `control.py`: группы сигналов как у дорожного контроллера (`veh`/`ped`,
  `veh_A`/`veh_B`/`ped_A`/`ped_B`), фазы и переходные интервалы по ГОСТ Р 52289. На переходе
  задержка включения пешеходной фазы зависит от интенсивности; на пустой дороге и при разрыве
  в потоке зелёный даётся быстро; группа от N человек ускоряет вызов; есть предел ожидания.
  На перекрёстке фаза продлевается, пока подходят машины, пешеходы и спецтранспорт получают приоритет;
- `safety.py`: модуль безопасности, независимый от логики решений;
- `equipment.py`: связь с контроллером объекта, подхват управления на устойчивой фазе, heartbeat;
- `runtime.py`: выбор режима по исправности камер (адаптивный, деградированный, фиксированный
  план), минутная статистика.

**Центр** (`center/`) крутит узлы в реальном времени, пишет статистику и события в SQLite,
отдаёт видео камер с разметкой и данные админке.
